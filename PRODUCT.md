# DID LAB

<!-- impeccable:product-schema 1 -->

## Platform
web

## Users
An operator controlling a TurtleBot3 mission on desktop or mobile; a jury viewing the same public telemetry in Presentation Mode.

## Product Purpose
Observe robot location, current action, its reason, route, energy and progress, and issue mission commands through the existing public API.

## Capabilities and Constraints
React / TypeScript frontend. Russian default and Tatar switching persisted locally. Public ROS occupancy map, telemetry, estimated energy costs and research journal only. No hidden sample coordinates or judge terrain. Preserve API, ROS nodes, MissionManager, NavigationPlanner, EnergyModel and LLM implementation. Never claim physical stop without fresh stopped telemetry. Backend serializes operations; frontend cannot promise preemption.

## Brand Commitments
Scientific, precise, intelligent, calm, futuristic and premium. Replace mint-led identity. Operational console first, separate presentation view, full mobile control. Design decisions delegated by the user's complete transformation brief.

## Evidence on Hand
Existing frontend and API source, .impeccable/critique audit, synthetic public-API fixture. No real Gazebo result from visual testing.

## Product Principles
Safety and truthful state before decoration. Separate current, next and historical mission. Data graphics retain physical coordinates and distinguish estimates from observations.

## Accessibility & Inclusion
Keyboard focus, readable typography, reduced motion, approximately 44px touch controls and textual map summary. TT terminology requires native-speaker review.
