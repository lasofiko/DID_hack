# Подключение planner Сони

Агент один. `MissionManager` выбирает источник решения внутри режима
`algorithmic` или `llm`; безопасность, движение, сбор и возврат остаются у него.
Настоящего LLM-клиента и готовой реализации Сони в репозитории пока нет.
API-ключ не нужен для algorithmic и fallback, вымышленные ответы не используются.

Контракт из `did_core/ports.py` сохранён:

```python
async def propose(observation: Observation, feedback: str = "") -> Subgoal:
    ...
```

Observation содержит только sim_time, pose в map/метрах, battery, noisy signal,
времена сенсоров и obstacle_ahead. Копия наблюдения передаётся planner, поэтому
изменение входного словаря не изменяет состояние робота. Скрытых целей, стоимости
зон и расписания событий в наблюдении нет.

Ответ содержит ровно четыре поля:

```json
{"action":"go_to","target":{"x":-1.5,"y":-0.5},"reason":"Проверить наблюдаемый сигнал","hypothesis_id":null}
```

action: explore/go_to/collect/return_to_base; target нужен для explore/go_to и
должен быть конечной достижимой точкой публичной карты. Для collect и
return_to_base target=null. Пока внешнего реестра гипотез нет:
hypothesis_id должен быть null. collect проверяется по подтверждённому медианному
сигналу, движение — через A*, запас возврата и safety watchdog.

Реализация команды должна находиться в `packages/ml/did_ml`. Создайте функцию
без аргументов, возвращающую объект с async propose; конфигурацию/секреты она
читает только на сервере. Точка подключения — переменная
`DID_PLANNER_FACTORY=did_ml.planner:create_planner` в Compose environment.
Это пример адреса будущего модуля, **не готовый/проверенный LLM-запуск**.
Импорт разрешён только из пространства did_ml. Пакет Марии не изменялся.

В браузере выбрать Planner mode: LLM. Если factory не задана/не импортируется,
agent пишет понятный fallback и работает алгоритмически. Для каждого решения
не более двух попыток propose, каждая ограничена planner_timeout=3 секунды.
Невалидные ответы дают безопасный feedback следующей попытке; затем fallback.
Текст исключений внешнего клиента не публикуется: журнал содержит только класс
ошибки, чтобы случайно не передать URL/API-ключ из provider exception.
Источник в `/did/agent/knowledge` и интерфейсе — LLM только после принятия
валидного ответа. В algorithmic planner вообще не вызывается.

Проверены тесты валидного test-double, неверного ответа, timeout двух попыток и
отсутствия вызовов в algorithmic. Это проверка границы, **не проверка LLM API**.
Соне нужны собственная factory, внешний клиент и проверка её зависимостей
в Docker; зависимости не устанавливаются автоматически произвольной командой.
