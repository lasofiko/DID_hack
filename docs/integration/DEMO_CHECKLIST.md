# Финальная демонстрация DID LAB

Дата проверки: 9 октября 2026. Итоговые ограничения — в [FINAL_RELEASE_REPORT.md](FINAL_RELEASE_REPORT.md).

Статус: NOT READY. Настоящий физический LLM-цикл не подтверждён. Два Start
через UI дали HTTP 503; диагностический API Start прошёл, но provider дал timeout.
Fallback нельзя выдавать за DeepSeek. Подтверждённый демонстрационный сценарий:
EASY seed 2 Algorithmic. Это не утверждение готовности всего релиза.

## Запуск на проверенной машине Apple Silicon

Из корня интеграционного worktree:

```sh
UBUNTU_MIRROR=https://mirror.yandex.ru/ubuntu-ports docker compose -p did-final-integration build
docker compose -p did-final-integration up -d
docker compose -p did-final-integration logs --tail 50
docker compose -p did-final-integration exec -T simulation bash docker/entrypoint.sh python3 scripts/ros_smoke.py
```

Проверить отсутствие другого Gazebo/издателя скоростей в ROS domain 42.
Первый запуск требует доступных моделей Gazebo Fuel; недоступная модель блокирует
появление odom/scan/clock. Не запускать `ros_smoke.py --move` рядом с агентом.

Открыть http://localhost:3000. Дождаться «Система подключена» и «Ожидание».
Карта должна загрузиться, батарея — около 60. Наличие страницы без сенсоров
не означает готовность стенда. Пассивный smoke должен подтвердить сообщения,
360 лучей, TwistStamped и TF map → base_scan.

## Показ

1. Выбрать EASY («Простой»), seed 2, Adaptive, Algorithmic. Параметры относятся
   к следующему запуску. Для чистого опыта использовать «Новая сессия», затем Start.
2. Показать изменение реальной позы и измеренной траектории. При необходимости
   увеличить карту кнопкой «+»: OccupancyGrid включает большой неизвестный край.
3. Включить «Режим презентации». Показать наблюдение, принятое действие и причину.
   Источник Algorithmic не называть LLM.
4. Показать энергетические ячейки, число принятых/отклонённых измерений и журнал.
   Оценки не являются истинными коэффициентами грунта.
5. Переключить TT и RU. Технические сообщения журнала могут оставаться английскими.
6. Показать Pause/Resume, затем Return. Если нужен немедленный операторский
   останов — STOP; ждать свежего состояния stopped и подтверждения ROS-команд.
   HTTP-ответ сам по себе не доказывает физическую остановку.
7. Reset выполнять после остановки: он уничтожает текущую сессию и пересоздаёт мир.
   После демонстрации остановить собственный стенд:

```sh
docker compose -p did-final-integration down
```

Тома не удалять. Не менять safety, reserve=8 или return_factor=1.5 ради результата.

## При ошибке

При stale/offline не доверять старой позе и маршруту. STOP может ожидать завершения
серверной операции; проверить журнал backend/ROS. Если подтверждения нет,
завершить только собственный Compose-стенд и считать проверку остановки BLOCKED.
Не отправлять повторные Start/Resume после неизвестного результата. Устранить
причину, создать новую сессию и снова проверить сенсоры.

## Что можно утверждать

Показывать только фактически записанные результаты текущего отчёта. Автотесты,
кинематические fixtures и Gazebo — разные уровни доказательств. Gazebo использует
локального mock-судью, а не официальный стенд соревнования и не реальный робот.

Два прежних вызова MAI/DeepSeek подтверждены синтетическими публичными данными.
Они не доказывают физическую LLM-миссию. Без ключа режим LLM может перейти на
Algorithmic; видимая выбранная настройка не доказывает источник решения.

Нельзя заявлять гарантированную доставку всех образцов, отсутствие физических
контактов без contact instrumentation, превосходство Adaptive на основании
единичных прогонов или готовность релиза при проваленном критическом gate.

## Настоящий MAI/DeepSeek

Пользователь настроил ключ в основной копии `/Users/kirito/Desktop/DID_hack/.env`.
Интеграционный worktree не содержит своей копии секрета. Чтобы подключить этот
файл, сначала подтвердить stopped/finished и отсутствие активного эксперимента,
затем пересоздать контейнер без повторной сборки:

```sh
docker compose --env-file /Users/kirito/Desktop/DID_hack/.env -p did-final-integration up -d --no-build --force-recreate
```

Простой `restart` не обновляет environment. Не выводить `docker compose config`
или environment целиком. Проверять только `bool(DID_LLM_API_KEY)`. Файл `.env`
исключён из Git в основной рабочей копии. Ключ никогда не вводится в React UI.

Выбор LLM в форме — только запрос режима. Для утверждения о настоящей модели
нужны `source=provider` в ML-журнале, принятие цели, фактическое выполнение и
результат через ResearchBridge. Fallback показывать отдельно и не называть LLM.
